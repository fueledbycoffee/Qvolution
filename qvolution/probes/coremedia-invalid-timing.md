# Typed invalid sample timing data

## Interface sources and explicit data policy

Vendored CoreMedia/CMTime.h defines the fixed-width time fields and flags; its existing CMTime.c canonical invalid value has zero value/timescale/flags/epoch. Vendored WebCore PAL CoreMediaSPI.h supplies timing fields in order duration, presentationTimeStamp, decodeTimeStamp, each CMTime (clean-room rung2). That header's Windows-only pack4 is not copied as a macOS ABI rule.

Apple documents [CMSampleTimingInfo](https://developer.apple.com/documentation/coremedia/cmsampletiminginfo), its three public time properties and [invalid](https://developer.apple.com/documentation/coremedia/cmsampletiminginfo/invalid). The public [documentation JSON](https://developer.apple.com/tutorials/data/documentation/coremedia/cmsampletiminginfo/invalid.json) Objective-C variant declares `extern const CMSampleTimingInfo kCMTimingInfoInvalid;` (rung3). It does not provide a byte-level initializer/alignment guarantee.

Conservative project policy (rung6 where exact native bytes are unspecified): the invalid timing aggregate contains three copies of the implementation's canonical kCMTimeInvalid model, all fields zero with Valid flag clear. This is actual typed invalid data, not a void pointer, function, successful sample or media-operation stub. Native Apple byte/alignment equality is not independently observed or claimed. Use existing CMTime C ABI naturally; no invented special packing, timestamps, valid flags, codec data or sample-buffer implementation. Public field order/size checks establish the project layout, not native platform measurements.

## Original runtime regression

The before-capable isolated build of coremedia-invalid-timing.c needs CoreFoundation and ordinary dlopen support, with no direct CoreMedia link or arguments/GUI. The integrated guarded target deliberately links CoreFoundation+CoreMedia and adds the compile-only public-header probe. It loads the real framework and looks up existing invalid/valid-zero time exports as controls, then the missing typed aggregate. Before-capable ProbeSampleTimingInfo independently declares public fields using vendored CMTime. It checks all three against actual existing invalid export fields, modifies a separate local copy to valid zero without modifying exported/owned invalid data, exercises absent-symbol negative control and retains a value copy after closing the library handle. Comparisons use fields, not padding bytes. No sample/decoder/Firefox workflow is fabricated or qualified.

The original probe compiles as C for x86_64+i386 using isolated compiler outputs. Existing saved AppKit recipe's forced Objective-C Foundation umbrella is removed for C; CoreFoundation and vendored headers remain. The candidate now defines the public type/const declaration in CMSampleBuffer.h and actual typed zero aggregate in the already-built CMSampleBuffer.c. Exact production CoreMedia compiler recipe, adapted only for clone input/header and isolated outputs, compiles fat x86_64+i386 successfully. The compile-only header TU verifies const pointer type, field offsets/size and natural existing CMTime alignment on both architectures. An isolated CMake harness evaluates the actual probe block with/without CoreMedia and checks target/source/link guards; it is not a full superproject configure/build. No guest launch or shared build/stage was performed by the author.

Coordinator before: positive time controls pass, new aggregate export is absent; exit1 in1.587s, exact-prefix shutdown0 (logs/invalid-timing-before.json). Independent terminal source review found no concrete blocker; candidate runtime/unchanged Firefox retake remains pending coordinator integration. No native byte/packing equivalence or media operation qualification is implied.
