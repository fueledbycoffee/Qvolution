# Guest-prefix URL handler preferences

Apple publicly declares [LSSetDefaultHandlerForURLScheme](https://developer.apple.com/documentation/coreservices/1447760-lssetdefaulthandlerforurlscheme) and [LSCopyDefaultHandlerForURLScheme](https://developer.apple.com/documentation/coreservices/1441725-lscopydefaulthandlerforurlscheme) as preferred-handler bundle-ID setter/getter, thread-safe since10.4. Capability metadata comes from CFBundleURLTypes. URI validation/canonical lowercase follows [RFC3986 section3.1](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.1). Bundle IDs follow Apple's published [CFBundleIdentifier character set](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CoreFoundationKeys.html): nonempty ASCII letters/digits/hyphen/period; reverse-DNS form is recommended, not an invented mandatory label count.

The setter now commits a real per-guest-user preference in `/private/var/db/qvolution-url-handlers-<uid>/preferences.db`, a project-owned guest-prefix SQLite store. This is not Apple's private database layout. The namespace is an owned0700 directory; main database and existing journal/WAL/SHM files must be owned0600 regular files. Symlinks/insecure existing paths are rejected without chmod or overwrite. New main files are closed while still unpublished, then atomically linked without overwriting an existing store, avoiding POSIX-lock loss from raw closes on a published SQLite inode. SQLite owns all subsequent main-file descriptors; statements bind inputs, SQLite serializes processes/threads with a bounded5s busy timeout, and a failure returns kLSDataUnavailableErr rather than success. Invalid arguments return paramErr; allocation failure returns memFullErr. These exact error mappings are project policy, not native error-equivalence observations. No host defaults, GNOME settings or D-Bus calls occur.

CopyDefault returns an owned immutable string read from committed storage. When no preference exists it consults only actual registered APPL bundle URL-scheme rows in the existing guest launchservices.db. GUESS: multiple candidates use deterministic lexical bundle-ID order; this is not Apple's best-handler ranking. An unreadable/corrupt preference store returns NULL with a generic diagnostic rather than silently overriding a broken explicit preference. Setter accepts a syntactically valid bundle-ID preference without claiming the app is installed/capable. CopyAll remains unsupported; no synthetic installed application is returned.

Build the original .m fixture against CoreFoundation/LaunchServices (Foundation may reexport CoreFoundation). It dynamically finds the setter after an existing CopyDefault symbol positive control, allowing parent baseline compilation without link failure. Default mode checks actual write/read replacement, ASCII scheme folding, mutable input independence, Copy snapshot ownership, invalid arguments/types/NUL, and concurrent independent key writes. It writes only original qvolution schemes in a disposable prefix.

Coordinator persistence/isolation sequence using fresh project-owned prefixes A and B:

1. A: `--set qvolution-isolation-original org.qvolution.A`.
2. A, separate guest process: `--expect QVOLUTION-ISOLATION-ORIGINAL org.qvolution.A`.
3. B: `--expect-none qvolution-isolation-original`.
4. B: `--set qvolution-isolation-original org.qvolution.B`.
5. A: `--expect qvolution-isolation-original org.qvolution.A`; B: `--expect qvolution-isolation-original org.qvolution.B`.
6. Shut down each exact prefix, restart A and repeat its expect check. No global state or host helper should be altered.

Failure gate uses another fresh prefix: query `--store-path`, then coordinator creates the owned0700 parent namespace and a directory at that exact guest-local store pathname before trying `--expect-write-failure qvolution-failure-original org.qvolution.Fixture`. This must report honest storage failure and never a successful registry roundtrip. Do not block/rename a store belonging to another test or user app.

For fallback, coordinator may register an original own-source .app with CFBundleIdentifier `org.qvolution.URLCapabilityFixture`, CFBundlePackageType APPL and CFBundleURLTypes claiming `qvolution-capability-original` through the existing `launchservicesd --register` helper, then use `--expect qvolution-capability-original org.qvolution.URLCapabilityFixture` without setting an override. Use only an executable compiled from our original fixture/source, not a vendor file or invented native executable. Registering capability metadata is not a runnable-app qualification.

`url-handler-locking.m` is a separate original fixture linked with LaunchServices/CoreFoundation/sqlite3, run only in a fresh disposable prefix. `--lock-conflict` holds a real dirty SQLite transaction, starts a concurrent public setter and a fresh exec process making60 immediate write-lock attempts. Every external attempt must fail specifically SQLITE_BUSY while the original transaction remains held, and the public setter must still be waiting. After rollback the queued setter must commit and the external unlocked positive control must succeed. This detects the [SQLite-documented POSIX raw-close lock hazard](https://www.sqlite.org/howtocorrupt.html): opening/closing a raw fd to an existing SQLite inode can cancel another local connection's OS locks, even when its SQLite state still claims them.

`--path-policy` checks real rollback journal/WAL/SHM permissions and committed reads, then deliberately weakens only its own test main/directory permissions or installs original sidecar symlinks/insecure files. The API must reject without overwriting the original preference, adjusting those modes, or mutating an original sentinel. It restores/removes only the objects it created. This is not a test to run against another user/app's existing store. The production creation path uses a random unpublished inode, closes it before atomic no-overwrite link publication and never raw-opens/closes the published main or sidecars. Existing insecure/foreign/symlink paths are unsupported with honest errors, not silently repaired.

Additional author-only native source-helper evidence in task scratch extracts the actual creation helper, compiles against real native SQLite and holds the original transaction across a local helper thread plus independent exec writer. The initial raw-preflight version fails its lock assertion; corrected actual helper passes. This is POSIX/helper evidence, not a guest API, bundled-SQLite, persistence or prefix-isolation result. All those guest gates remain coordinator-owned.

Actual URL dispatch remains a separate required lane: LSGetApplicationForURL currently uses the host web/mail policy or file-extension lookup; LSOpenFromURLSpec handles file apps/host links and rejects other schemes. Neither currently reads this preference to route a custom URL to a selected bundle or delivers its URL-open event. A registry roundtrip does not complete handler integration. Future work must resolve scheme→preferred/capable bundle→real application URL, preserve host policy, deliver the original URL to an actual guest handler and verify its observable reception. No URL is opened by these fixtures.

Provenance: public Apple/RFC interfaces and repository LSInfo/schema/dispatch source. No Apple binary or vendor resource inspected. Candidate compilation, runtime, persistence, prefix isolation, failure and unchanged vendor retake remain coordinator gates.
