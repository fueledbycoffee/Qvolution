# Attachment type-hint data export only

[Apple UNNotificationAttachmentOptionsTypeHintKey](https://developer.apple.com/documentation/usernotifications/unnotificationattachmentoptionstypehintkey) and its public documentation JSON Objective-C declaration specify `extern NSString * const` (clean-room rung3). The option's value is an NSString UTI hint; when absent a real attachment implementation may infer type from filename extension. This lane adds only the actual immutable data export and public declaration, not that implementation.

Existing UserNotifications attachment/umbrella headers were inspected first (rung2); no option data keys currently exist. The attachment source is already built and the existing umbrella imports its header. Only this observed key is added; root's permitted names-only demand analysis found no other attachment-options-family constant required by the unchanged Discord guest framework.

Exact native key bytes are not supplied by the consulted public documentation or independently measured. Explicit project policy (rung6) uses the unique full public symbol name `UNNotificationAttachmentOptionsTypeHintKey` as its NSString value, retaining a clear stable namespace. This is not a claim of native literal equality, attachment option serialization/interoperability, UTI inference, permission, notification delivery or success. No empty/function/void-pointer placeholder or guessed extra exports are added.

Original usernotifications-type-hint-key.m is before-capable: Foundation+dlopen only, no args/GUI. It loads the actual framework, checks an existing attachment class's metadata and actual Foundation NSCocoaErrorDomain data (there are no preexisting UserNotifications keys to pretend are controls), then requires a genuine nonempty NSString key. Generic absent/explicit-UTI/copied-dictionary states, creation-pool lifetime and absent-symbol negative are checked while the image remains loaded. No attachment class methods are invoked and no file/notification is created. Runtime fixture does not independently prove native byte equality. Compile-only header TU checks actual NSString*const data pointer type through direct attachment header and existing umbrella.

Coordinator before: controls pass, new data lookup fails, exit1 in1.709s with exact-prefix shutdown0, logs/un-type-hint-before.json. Actual production compiler recipe, adapted for cloned input/header and scratch output, compiles x86_64+i386 fat successfully; runtime and header TUs compile isolated. Guarded UserNotifications target links Foundation and depends on framework without requiring the missing data at fixture link time. Candidate guest and unchanged Discord/VSCode retakes remain root-owned/pending; no full framework or app qualification.
